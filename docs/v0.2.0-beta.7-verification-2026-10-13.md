# Beta.7 verification — 2026-10-13

## Scope and cause

The paired-phone manager's **Open scanner on phone** window displayed only a
public homepage URL. Unlike the pairing QR, it had no phone-open signal, so
successful scanning could not close the PC window automatically.

The return QR now uses an existing short-lived relay session solely for an
open acknowledgement. The fragment contains version, temporary session ID,
temporary token and expiry, not the pairing secret or any stored credentials.
The phone strips the fragment and POSTs only to its same-origin opened route.
The PC closes on that event and deletes the unused session. No approval,
replacement, registration or store mutation occurs in this return path.
Expiry and manual close also clean up. Session-creation failure falls back
to the public homepage QR with a manual-close explanation.
