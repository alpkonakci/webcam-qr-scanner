# Webcam QR Scanner v0.2.0-beta.9

Limited Windows x64 / Phone-to-PC pre-release. Not a stable release or an independently audited protocol. Previous releases remain available.

## Fixes and hardening

- Fixed a first-start race when concurrent receivers initialize the persistent replay ledger. The complete, protected database is published atomically without overwriting another process's ledger. Existing empty/corrupt ledgers still fail closed; replay protection is not reset or bypassed.
- Removed the blanket inline JavaScript allowance from the Next/Vercel phone site's CSP. Each page response has a fresh 128-bit nonce and private/no-store HTML. Framework scripts remain functional; unauthorized inline scripts are blocked.
- Retained the inline-style allowance needed for image-crop geometry. Development-only eval is not enabled in production. The historical Cloudflare/vinext Worker policy is outside this change.

## Updating

Exit the old QR Scanner from its tray menu, extract the entire ZIP and open `QR-Scanner.exe`. Refresh https://qrwebcam.vercel.app on your phone. Normal production use requires no Vercel login or bypass secret.

Pairings are retained in the same Windows account and browser/site storage. Preview origins and different browsers have separate pairing storage; pair again on the production address if necessary. No database migration or user-pairing deletion is part of this update.

The EXE is unsigned, so SmartScreen may show a publisher/reputation warning. Verify the ZIP against `SHA256SUMS.txt`. MIT is unchanged, with no activation or license check. Application source, notices, required upstream sources and rebuilding instructions are included.

## Verification and limitations

The functional candidate passed 343 desktop and 147 web tests, production build, lint/type checks, and Chromium nonce enforcement, image-QR/repeated-scan and synthetic camera checks. The user reported that all requested HTTPS-preview phone flows passed; the final report did not specify a device/browser matrix. Versioned release CI, package/source matching and self-test checks are verified separately before publication.

Independent protocol/cryptography review, expanded clean-machine/browser/installed-mode acceptance, dynamic screen-reader coverage and live valid-credential cross-device authorization checks remain open. Rate-limit coverage needs further review. Hard-link support is required for initial replay-ledger publication; unsupported storage fails closed. ACK loss can leave delivery uncertain; this is not a durable process-crash recovery queue.
