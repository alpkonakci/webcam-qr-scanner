# Beta.6 dependency remediation — 2026-10-11

Baseline: beta.5 / `a94541b`, branch `codex/vercel-supabase`.

## Finding and remediation

The initial full npm audit reported eight high package findings propagated
from braces <=3.0.3, GHSA-vfj7-8cjw-p6xm. Registry metadata still listed braces
3.0.3 as latest. npm's proposed forced fixes downgrade Next lint to 14.2.35
and vinext to 0.0.15; those incompatible downgrades were not selected.

Installed callers were examined: Next's get-root-dirs uses globSync with
onlyDirectories; Vite dynamic-import uses sync with cwd and extension patterns.
The private `pwa/vendor/build-glob` adapter implements these calls through
tinyglobby 0.2.17 (fdir/picomatch), bounds pattern count/length/nesting, preserves
absolute input paths, removes directory trailing slashes and disables automatic
directory expansion. Unknown options fail explicitly. No vulnerable source
was renamed or copied, no audit exception was added.

The dependency is pinned as a root file development dependency; npm override
`$fast-glob` redirects both consumers. Initial nested-link lock entries were
invalid; the final deduplicated lock was regenerated and checked from clean
`npm ci --ignore-scripts`, followed by a valid `npm ls fast-glob --all`.
The lock retains Linux native optional packages required by Vercel.

The runtime source/Next trace/Vite module gates now also exclude tinyglobby,
fdir, the private package and its resolved vendor directory. Next lint and
Cloudflare/Vite support remain enabled.
