# v0.2.0-beta.2 — Usability improvements

**Limited beta / pre-release.** Recommended stable release: **v0.1.1**.
Beta.1 remains available; this release does not replace an audited stable build.

## Changes since beta.1

- **Return to your phone scanner:** Paired Phones → Open scanner on phone
  displays a reusable public-homepage QR. Reopen the same paired phone browser
  and continue sending without another pairing. This QR contains no credentials
  and does not grant or replace access.
- **Clearer phone instructions:** a compact saved-connection reminder explains
  bookmarking the page and using Scan QR inside the scanner to send links.
  The ordinary phone camera opens websites directly.
- **Small screen-QR retries:** selected crops get bounded enlargement, quiet
  borders and contrast retries. Distinct QR payloads still trigger the existing
  ambiguity protection; received links still require PC approval.
- **Helpful unreadable-QR message:** use a full-size image, enlarge the original
  page and leave a margin around the code. Low-resolution thumbnails can lose
  too much detail to decode; no payload is guessed.

## Install or update

1. Download the Windows x64 ZIP and `SHA256SUMS.txt` from **Assets**.
2. Verify the ZIP's SHA-256 against the checksum file.
3. Exit the running QR Scanner, extract the entire ZIP into a new folder, and
   run `QR-Scanner.exe`. Keep its license files. Python, PowerShell configuration
   and a Vercel bypass secret are not required for normal use.

Existing pairings stay in the same Windows user's protected settings; they are
not stored in the ZIP. A different Windows account or phone browser needs its
own pairing, even if the displayed PC name is the same. If the phone offers an
old connection, choose **Replace pairing** to connect to the intended account.

## Known limitations

- Tiny, blurry or distorted QR thumbnails can remain unreadable. Protected/DRM
  video can appear black in captures. Some Android cameras require Google Lens.
- Saved phone credentials belong to the browser used for pairing; private mode,
  cleared site data or a different browser can require pairing again.
- The EXE is unsigned and Windows may show a publisher/SmartScreen warning.
- Full reboot/restart, offline receiver and interrupted-network acceptance is
  not fully recorded for both phone platforms. Deployed forced Realtime fallback
  and healthy-channel timing evidence remain incomplete.
- Broader Auth/error-path/live-data privacy review and independent protocol and
  cryptography review remain open. This is not a security certification.
  See the [verification report](https://github.com/alpkonakci/webcam-qr-scanner/blob/v0.2.0-beta.2/docs/v0.2-beta-verification-2026-09-30.md)
  and [release checklist](https://github.com/alpkonakci/webcam-qr-scanner/blob/v0.2.0-beta.2/docs/v0.2-beta-release-checklist.md).
