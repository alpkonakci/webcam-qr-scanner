# Webcam QR Scanner v0.2.0-beta.3

Limited Windows x64 / Phone-to-PC pre-release. Latest stable remains v0.1.1.
This is a new candidate, not a replacement of the beta.1 or beta.2 assets.

## What's changed

- Persist scoped replay protection across receiver reconnects and application
  restarts. The local SQLite ledger contains current-user DPAPI-encrypted
  message-ID digests and expiry metadata, never link URLs or pairing keys.
  Unavailable or corrupt replay storage fails closed.
- Keep relay duplicate-message tombstones until the original link expiry,
  independently of the short receipt lifetime. Completed/rejected messages
  discard encrypted link contents; expired receipts are cleaned separately.
- Automatically check an existing pending delivery while the phone result
  stays open. These are status requests, not repeated link sends. A missed
  authenticated receipt shows **Check your PC**, never a false success.

## Update

Fully exit the old QR Scanner (including its tray process). Extract the entire
new ZIP into a separate folder and open QR-Scanner.exe. Existing pairings are
retained within the same Windows account. Refresh qrwebcam.vercel.app on the
phone after the new web deployment. No PowerShell or bypass secret is needed
for normal use. SHA256SUMS.txt covers the ZIP and the executable inside it.

## Verification and limits

254 desktop and 54 PWA regressions passed, including a separate-process
Windows DPAPI replay test. Production build, TypeScript, lint and packaged EXE
self-test passed. The Supabase migration passed an isolated PostgreSQL test
whose synthetic fixtures were rolled back; no real pairings were used.
The migration was subsequently applied with explicit user confirmation.

This is not independent protocol/security certification or a completed
iPhone/Android device matrix. Realtime fallback timing and broader privacy,
policy and log review remain release gates before main/stable promotion.
The EXE is unsigned and may trigger Windows SmartScreen. Protected video may
appear black in screen capture; QR images with insufficient original pixels
cannot be recovered by enlargement.

Receipt verification still has a ten-second lifetime. Background suspension,
reload or another phone tab can miss that window; success is then not claimed.
Replay protection is at-most-once, not guaranteed delivery across a crash.
It does not defend against deleting/restoring the ledger under the same user.
Expired local records are pruned on a later valid message; relay cleanup is
probabilistic, not an immediate physical-erasure guarantee.
