# Webcam QR Scanner v0.2.0-beta.8

Limited Windows x64 / Phone-to-PC pre-release, not a stable or independently audited protocol release. Previous releases remain available.

## Improvements

- Turkish/English interfaces, clear saved-pairing, PC reachability and delivery states, settings/about and Windows startup preference.
- Native desktop controls for keyboard navigation, visible focus and accessible names; corrected settings foreground navigation and high-DPI layout.
- Phone home-screen guidance that explains browser/installed-mode storage differences instead of promising pairing transfer.
- QR creation and local image/clipboard QR reading, including automatic single-code decoding and multiple-code selection.
- Packaged TLS runtime data and startup self-test fixes.
- Verified incoming links still reach the local confirmation callback once when an ACK transport fails; replay protection remains enabled and explicit HTTP rejection remains fail-closed.
- Patched development dependencies (fast-uri, zod and Miniflare-scoped undici); the full and production npm audits reported zero known vulnerabilities at verification time.

## Updating

Exit QR Scanner completely from its tray menu, extract the entire ZIP and open `QR-Scanner.exe`. Do not run the old and new copies simultaneously. Refresh the phone website at https://qrwebcam.vercel.app.

Saved pairings in the same Windows account and the same browser/site storage are retained. Preview domains and different browsers do not share pairing storage; pairing on a preview does not automatically pair the production site. No Vercel account or preview bypass secret is required for normal production use.

The EXE is unsigned; Windows SmartScreen may display a publisher/reputation warning. Verify the download against `SHA256SUMS.txt`. MIT remains unchanged; no activation or user-license check is added. Immutable application source, dependency notices, required upstream source archives and rebuilding instructions are included.

## Verification and limitations

The preceding candidate passed 338 desktop and 145 web tests, production build, lint, typecheck, Windows/web/PostgreSQL CI, packaging/source checks and EXE self-tests. The user confirmed pairing → send → remove → re-pair → exit. Versioned release verification is recorded separately; automated tests do not replace real-device acceptance.

Latest clean second-Windows-environment acceptance, independent Chrome/installed-PWA storage acceptance, broader dynamic screen-reader/error announcements and live credential-level revocation checks are not all complete. Independent protocol/cryptography review remains required before stable promotion. ACK loss can leave phone delivery status uncertain; the receiver is not a durable process-crash recovery queue. Zero audit findings is not a complete security guarantee.
