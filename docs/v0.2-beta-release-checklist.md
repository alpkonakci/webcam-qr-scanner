# v0.2.0-beta.1 release checklist

[Türkçe](v0.2-beta-release-checklist.tr.md)

This checklist is the release gate for the Phone-to-PC beta. A checked source
code test is not a substitute for a real-device or deployment check.

## Current decision

- Target: `v0.2.0-beta.1` GitHub **pre-release**.
- Stable release: `v0.1.1` remains the recommended version.
- Status: **not ready to publish** until the Vercel preview and real-device
  sections below pass.
- The existing Sites/Cloudflare deployment remains available for at least 48
  hours after the new production origin is verified.

## Automated gates

- [ ] All Python desktop tests pass.
- [ ] The packaged EXE passes `--self-test`.
- [ ] PWA build, typecheck, lint, and all PWA tests pass.
- [ ] Revocation tests prove remote-first removal and fail-closed local storage.
- [ ] A revoked PWA pairing is deleted only after an exact `pair_revoked` error.
- [ ] Secret scanning finds no URL payload, token, key, Authorization header, or
  real deployment secret in tracked files or generated browser assets.

## Vercel preview gates

- [ ] Vercel is connected to the GitHub branch with `pwa` as Root Directory.
- [ ] `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, and
  `RELAY_RATE_LIMIT_PEPPER` are configured in Vercel, never committed to Git.
- [ ] `/healthz` returns the expected no-data response.
- [ ] Anonymous Supabase device authentication succeeds without email, phone,
  or an account screen.
- [ ] The private Realtime device channel connects.
- [ ] Forced Realtime interruption recovers through the five-second poll.
- [ ] A healthy Realtime connection uses only the 60-second safety resync.
- [ ] API errors expose stable codes without leaking request bodies or secrets.

## Real-device matrix

Run every row once on iPhone Safari and once on Android Chrome.

- [ ] Pair without an email address, phone number, or app-store installation.
- [ ] Send over mobile data to a PC on another network.
- [ ] Show the hostname and full URL on the PC; open only after PC approval.
- [ ] Show an HTTP warning and reject non-HTTP(S) schemes.
- [ ] Preserve the pairing after browser, desktop app, and PC restarts.
- [ ] Deliver through Realtime and through the forced recovery-poll path.
- [ ] Refuse to store a new message while the PC is offline.
- [ ] Remove access from Windows; the old phone receives `pair_revoked`, clears
  its IndexedDB pairing, and offers pairing again.

Record device model, OS/browser version, network type, production URL, test
time, and result in the pull request. Do not attach private QR codes or URLs.

## Privacy and operations review

- [ ] Vercel function logs contain no URL, Authorization header, token, key,
  QR image, or ciphertext body.
- [ ] Supabase logs contain no URL, Authorization header, token, key, QR image,
  or ciphertext body.
- [ ] Stored rows contain only documented token hashes, opaque routing data,
  short-lived encrypted envelopes, and operational timestamps.
- [ ] The public PWA bundle contains the publishable key only; it does not
  contain the Supabase secret key or rate-limit pepper.
- [ ] Third-party notices match the exact Windows and PWA dependency versions.

## Packaging and release

- [ ] Build and test the ZIP on a clean Windows user account or clean machine.
- [ ] Verify `SHA256SUMS.txt` against the downloadable ZIP.
- [ ] Open a Draft PR and attach the automated and manual test evidence.
- [ ] Merge only after all required checks above pass.
- [ ] Publish `v0.2.0-beta.1` as a GitHub pre-release with the ZIP, checksum, and
  release notes; do not mark it as the latest stable release.
- [ ] Keep both hosting systems available for at least 48 hours.
- [ ] Remove the old deployment and unused cloud resources only after separate,
  explicit approval.

An independent protocol and cryptography review is required before promoting
the beta to stable `v0.2.0`.
